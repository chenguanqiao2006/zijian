## 第一部分：位置判定规则

### 1. 自然语言定义

位置判定用于衡量当前收盘价在近250个交易日（约一年）高低点区间中所处的相对位置，以百分比形式量化，并将结果分为低位、中位、高位三档。

声明：原著提出了“位置决定性质”这一命题（见联网核实结论第1条），但未给出位置判定的量化阈值【未能核实】。本规则采用当前市场通用的250日高低点区间百分位法，属于整理者分析，非权威来源。

### 2. 输入数据

| 变量名 | 数据含义 | 数据类型 | 数据来源 |
|:---|:---|:---|:---|
| C[t] | 当日收盘价 | float > 0 | 行情数据源（前复权） |
| H[t], H[t-1], ..., H[t-249] | 近250日最高价 | float > 0 | 行情数据源（前复权） |
| L[t], L[t-1], ..., L[t-249] | 近250日最低价 | float > 0 | 行情数据源（前复权） |

### 3. 精确计算公式

250日高低点区间：

    HHV_250 = max(H[t], H[t-1], ..., H[t-249])
    LLV_250 = min(L[t], L[t-1], ..., L[t-249])

位置百分位：

    position_pct = (C[t] - LLV_250) / (HHV_250 - LLV_250) × 100%

### 4. 判定条件

- 低位：position_pct < 30
- 中位：30 ≤ position_pct ≤ 70
- 高位：position_pct > 70

（注：30%与70%分档阈值非原著内容，为整理者分析，非权威来源。原著仅定性区分“低位/高位”，见联网核实结论第3条。）

### 5. 边界情况

| 情况 | 处理方式 |
|:---|:---|
| 上市不足250日 | 使用上市以来全部交易日数据作为区间，标注“窗口收缩”；上市不足20个有效交易日不判定 |
| 停牌后首日 | 停牌日数据保留在250日窗口内（停牌期间价格不变）；若停牌超过250日，区间失效，不判定 |
| 新股上市首日 | 不判定（需至少20个有效交易日） |
| 除权除息日 | 必须使用前复权数据；除权除息导致的价格跳变不影响位置百分位（前复权已修正） |
| 数据异常（负数、空值） | 该日数据视为无效，HHV/LLV计算时排除无效数据 |
| HHV_250 == LLV_250（区间为零） | 分母为0，标注“区间无效”，位置归为“mid”但附加警告字段 |

### 6. 输出格式（JSON）

    {
      "position_pct": 52.0,
      "position": "mid",
      "HHV_250": 20.00,
      "LLV_250": 10.00,
      "window_days": 250,
      "data_quality": "valid",
      "note": "位置判定为非原著扩展规则，阈值30%/70%为整理者分析，非权威来源；仅作为量柱信号的过滤器，不单独作为交易信号"
    }

### 7. 确认日定义（零未来函数）

位置判定为当日确认信号，确认日为T日收盘后。仅使用C[t]及H[t-249..t]、L[t-249..t]（全部为当日及之前数据）。无未来函数。

### 8. 测试用例

测试用例1（低位判定）：

- 输入：C[t]=11.00，近250日HHV=20.00，LLV=10.00
- 计算：position_pct = (11.00 - 10.00) / (20.00 - 10.00) × 100 = 10% < 30
- 预期输出：position = "low"

测试用例2（中位判定）：

- 输入：C[t]=15.20，近250日HHV=20.00，LLV=10.00
- 计算：position_pct = (15.20 - 10.00) / (20.00 - 10.00) × 100 = 52% ∈ [30, 70]
- 预期输出：position = "mid"

测试用例3（高位判定）：

- 输入：C[t]=18.50，近250日HHV=20.00，LLV=10.00
- 计算：position_pct = (18.50 - 10.00) / (20.00 - 10.00) × 100 = 85% > 70
- 预期输出：position = "high"

测试用例4（区间为零边界）：

- 输入：C[t]=15.00，近250日HHV=15.00，LLV=15.00
- 计算：HHV_250 == LLV_250，分母为0
- 预期输出：position = "mid"，标注“区间无效”，附加警告（data_quality = "degenerate_interval"）

## 第三部分：全局输出字段规范

所有量柱信号的输出JSON，必须包含以下两个字段：

- **position**：位置判定结果（low / mid / high）
- **nature**：基于位置和信号类型，从映射表查得的中文性质描述

示例（以倍量柱为例）：

    {
      "signal_id": "double_volume",
      "date": "2026-10-05",
      "is_signal": true,
      "position": "low",
      "nature": "主力建仓信号",
      "values": { ... }
    }

### 规则

1. 位置判定失败（数据不足、区间无效、上市不足20日等）时，position = "unknown"，nature = "无法判定性质"。
2. 位置为“mid”时，nature 默认标注为“中性/换手性质”，除非原著对中位性质有明确定义（如黄金柱中位=中继黄金柱，具有接力性、加速性）。
3. 位置为“low”或“high”时，nature 从映射表对应单元格取值；单元格标注【原著未明确定义，为整理者分析，非权威来源】的，nature 输出时须附加该标注。
4. 原著有明确定义的性质，nature 直接输出原著表述，不附加整理者标注。

## 第四部分：本文件与其他批次的关系

1. 本文件为全局规则，优先于任何批次的规格卡。
2. 批次1（高量柱/低量柱/倍量柱/平量柱/缩量柱/梯量柱/黄金柱）、批次2（将军柱/元帅柱）及后续所有批次的规格卡，在输出JSON中必须引用本文件定义的position和nature字段。
3. 若批次规格卡与本文件冲突，以本文件为准。
4. 位置判定为辅助过滤器信号，本文件将其升级为全局规则：所有量柱信号输出均须附带位置与性质字段，但位置判定本身仍不单独作为交易信号。
